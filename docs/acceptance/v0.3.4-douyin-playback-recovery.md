# 0.3.4 Mac 抖音播放恢复修复

基线为本地 `3f5a377`（桌面 / Sidecar 0.3.3，扩展 0.9.3）。本轮仅修复 Mac 桌面恢复流程，桌面与服务升为 0.3.4，扩展保持 0.9.3。未推送、发布、操作 Windows 或上传截图。

## 诊断事实

用户已有固定作品在实际 0.3.3 中再次普通解析失败，返回 `site_response_unavailable`。持久错误中存在提取器的 Fresh cookies (not necessarily logged in) 信息，但没有明确 403 或 JSON 空响应证据；不能把这句直接解释为用户未登录。

已安装 yt-dlp 2026.08.19 的 Douyin 提取器只请求 web detail 接口，无有效 `aweme_detail` 就抛出该提示。核对官方当前源码仍是相同入口，因此没有以盲目更新工具承诺解决。独立、受信任 CA 校验的匿名探测 HTTP 403，只证明该独立请求被拒绝，不冒充应用请求的响应状态。

隔离浏览器实际显示登录弹窗；首次 DOM 探针匹配隐藏内容而误报不可用，截图复核已纠正，不据此认定作品已删除。随后使用安装版 0.3.4 的原生浏览器会话和现有失败任务再次核验：可见扫码 / 验证码登录界面，没有可播放媒体，也未发现可见内容删除提示。站点操作停在本人登录步骤，没有自动登录、提交验证码、导出 Chrome 凭据或绕过验证。

## 修复

旧“使用内置登录重试”仍直接请求同一详情接口，且不会先打开播放页。现在“播放后重试原任务”打开原作品的内置浏览器窗口，显示明确操作指引和“重试原任务”按钮。

恢复只接受原作品页面中一个实际可见、已播放、具备名称且来自既有可信抖音媒体域的媒体。可见登录 / 验证提示时拒绝恢复；其他作品、未播放、隐藏、歧义和非可信媒体不进入原任务。此路径不重打详情接口、不读取凭据，只通过既有服务端恢复合同重试原 ID，合并同时点击。重复点击不会重新加载正在登录的原作品页面。

补齐抓取窗口加载完成与加载失败反馈；加载错误不显示网址或原始错误。专属单视频详情页可从页面标题补充作品名称，通用抖音标题保持未知。

## 尚需用户操作

在百纳中找到该失败作品，点击“播放后重试原任务”。在弹出的内置网页本人登录并完成站点要求的验证，正常播放自己有权访问的原作品，再点击顶部“重试原任务”。完成后才能验证原任务下载与真实成品完整解码；本轮不能宣称抖音下载已经成功或所有作品均可恢复。

Chrome 扩展 0.9.3 仍待用户手动加载；本修复使用百纳自身内置浏览器，不依赖 Chrome 管理页权限。可见播放、媒体匹配和站点允许访问是前提，付费、私密、删除、验证及不可访问内容不绕过。播放器为 blob / 无可用直链或没有可靠作品名称时仍会停止并保留原失败任务。
