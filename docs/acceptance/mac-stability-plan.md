# Mac 与 Chrome 稳定化计划

授权范围：冻结新增功能，集中 Mac + Chrome；YouTube / Bilibili 为正式支持候选。抖音在同包真实播放、抓取与原任务重试成功前标为实验性。Windows、签名、公证、自动更新新工程、五人试用、推送与公共 Release 不在本轮实施范围。

基线：本地 `8d85589`，实际安装桌面 / Sidecar 0.3.5，扩展源码 0.9.3；开始时工作区干净。历史结果只作线索，不计入本轮候选通过。

## 顺序与完成标准

1. 明确抖音实验性文案，复核错误恢复合同，构建 0.3.6 同源 Mac 候选；最终记录完整安装包 SHA-256。
2. 使用独立应用 profile、数据库、输出和临时桥端口验证真实安装包。两站分别执行单条、批量、画质、音频、取消、失败重试、重复点击和应用重启恢复；通过可见输入与操作驱动。下载成功必须验证任务与文件身份、名称、目标目录、无意外重复任务、完整解码及所选媒体形态。短时可访问公开样本验证不扩大为全站保证。
3. 验证冷启动、启动器断管、隔离旧包升级、非零 Range 恢复和原成品安全。登录、失效链接、网络、暂不支持和程序错误分别记录真实观察或受控故障来源；受控故障不能冒充真实网站现象。
4. Chrome 必须区分桥协议与真实已加载插件。此前扩展管理页访问遭拒，不能用另一自动加载路径绕过。可先完成桥和隔离 popup 验证；实际版本或原生操作不明时记录阻碍，最后给用户正常重载所需的最小一步。
5. 任一阻断下载、崩溃、丢数据、错误视频问题先修复，再以新同源包重新执行受影响完整流程。每行只计入矩阵所绑定候选；不得混用旧包通过。恢复安装保存应用、数据、队列、历史、设置和成品哈希。

## 证据与发布判断

当前矩阵见 `mac-stability-matrix.current.json`，初始 31 行；本轮实际发现 HTTP403 误分类后补入独立拒绝访问行，最终共 32 行，状态仅为 passed / failed / not-tested / blocked；每行指向本轮证据并说明自动 UI、真实站点、受控故障或原生人工边界。单测、构建、包级 smoke 另记，不替代真实流程。

关键缺口：开始时 0.3.5 尚无上述完整网站操作复验；文件系统没有找到已安装 Downany 扩展 manifest，但解压插件可能不在该目录，因此实际 Chrome 扩展版本与启用状态仍未知；抖音旧任务失败，不具备稳定支持证据。无需还原旧五人试用门槛。

最终判定：所有正式候选必需行通过且没有崩溃、丢数据、下错文件或重复任务阻断，才可提出公共稳定发布。原生 Chrome 阻碍或网站验收失败存在时，只交付本地修复候选及具体下一步，不宣称稳定版已验收。新 Release / 推送须另行确认。

实施结果见 `v0.3.6-mac-stability.md`。实际安装已更新 0.3.6，插件候选已更新 0.9.4；原生 Chrome 仍须本人正常加载后验收，公共稳定发布判断按最终同包矩阵。
