## 修复与实际发现

网站 HTTP403 以前归为网络失败；现在独立为 `access_denied`，明确网站拒绝媒体请求，提供检查原网页、网页识别与诊断入口。主界面、插件 popup 与后台均阻止这种错误继续走同一路径重试，插件缓存保留错误码。不会把403推断为未登录、已删除或程序bug。官方稳定引擎核对仍为2026.08.19，未盲目换非稳定引擎或绕过站点控制；本轮修复解释和恢复合同，没有宣称已经消除YouTube全部拒绝。

B站需要先经过选集确认。真实双击“添加”时，第二下会落到刚挂载的遮罩并关闭确认。现在忽略双击的遮罩取消；正常单击取消仍生效。最终包定向与完整流程均验证只创建一个任务、文件正确且完整解码。

抖音在 README、站点列表与实际任务行明确标为实验性。匿名原链接再次跳到其他推荐作品，恢复被拒绝，原任务保留、没有新任务或成品；没有登录、扫码、验证码或真实下载成功。保护验证不等于完整抖音支持验收。

## 验证范围与统计

- 桌面 83 文件、664 项通过；Main / Renderer 类型检查和生产构建通过。
- Python 核心 / 数据 / Sidecar / CLI：1078 项通过、3 项跳过；跳过不计通过。
- 插件与升级/恢复脚本 Node 检查：11 个 TAP 用例通过；完整包检查另记。
- 同最终包两站分别执行单条、两条批量、360p选项、MP3、取消、受控断网后原任务双击重试、重复点击和暂停重启。成品均核对目标ID/分集、名称、输出目录、流形态、非零大小及完整解码；MP3内嵌封面不冒充视频轨。
- 三次全新profile/data的冷进程启动为801、886、885毫秒，服务版本一致且可连接；系统缓存未清除。构建阶段第一次Sidecar hello曾约19.3秒，保留其边界，不宣称重启系统或干净机器首装已覆盖。
- 实际Electron两次EPIPE后仍健康；隔离0.3.5→0.3.6升级保留设置、原任务ID、已完成文件和暂停状态，产生非零206 Range续传并完整解码；受控网络恢复与不覆盖旧成品五项通过。
- HTTP403/503与非媒体页由受控真实HTTP触发；不可用链接是实际YouTube响应。登录与未知错误只验证明确标注的种子展示，不冒充真实登录或把未知原因认定为程序bug。
- 插件生产popup通过隔离Electron展示验证连接/启动/断开、安全错误与禁止无效重试；没有自动加载Chrome插件或绕过管理页限制，此结果不计原生Chrome通过。

验收器曾把音频封面误判为视频轨，并漏掉B站选集确认步骤，已纠正。一次按应用名退出命中了同名隔离实例，受影响运行已作废，未计最终通过；后续按实际安装PID退出。所有首次和中断证据保留在本地，最终矩阵只采用上述SHA绑定结果。

## 实际安装与数据

保存旧0.3.5应用和完整数据回滚副本，验证备份与候选核心文件哈希，原子替换实际安装应用，以普通LaunchServices启动。实际桌面与下载服务均0.3.6、固定桥连接正常，46个原任务ID/选项、39条历史、全部原设置和31个已有成品哈希保留。实际界面已本地查看，原抖音任务显示实验性；未上传截图或私有数据。

## 剩余步骤与发布判断

先由本人在Chrome正常扩展界面加载/重载0.9.4，再执行原生连接、重连与发送验收。此前管理页访问拒绝仍有效，不以另一自动加载路径替代。YouTube匿名公开样本的间歇性403仍需通过合法原网页访问/正常会话进一步定位与复验，不能把当前候选当作已验收稳定版，也不能要求用户导出凭据或绕过验证。抖音保持实验性，不加入稳定支持承诺。

未推送、打标签、上传公共Release、操作Windows或扩展到签名/自动更新工程；没有恢复已取消的五人试用要求。此阶段交付本地候选和可继续执行的矩阵，公共稳定发布保持阻断。
