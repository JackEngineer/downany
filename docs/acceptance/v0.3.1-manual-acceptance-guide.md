# Downany v0.3.1 人工验收说明

本说明用于记录真人首次使用和 macOS / Windows 最终候选包的人工操作。自动化结果不能填写到这里，也不能代替任何一位试用者或平台操作员。

## 准备

1. 复制 `v0.3.1-manual-acceptance.template.json` 为 `v0.3.1-manual-acceptance-results.json`，保留模板不变。
2. 每个平台只使用该平台最终候选安装包，并将安装包 SHA-256 填入对应平台记录；同平台试用者必须使用相同校验值。
3. 试用内容应为已获授权、无需说明特殊登录步骤的公开视频。记录中不要保存网址、账号、Cookie、Token、真实姓名或私人文件路径。

## 五人首次使用

试用者必须从未使用过 Downany，记录代号固定为 `P1` 至 `P5`。观察员只提供安装包和一句任务：“请安装 Downany，添加这个视频并下载，完成后打开成品。”开始后不解释按钮、设置或操作顺序。至少一位试用者使用 Chrome 扩展添加视频；向该试用者同时提供候选扩展 ZIP，但不提前说明本地网络权限按钮应如何选择。

每位试用者依次完成：

1. `install`：安装并启动应用。
2. `add`：自行找到入口并添加视频；填写 `addMethod: "app"` 或 `addMethod: "extension"`。扩展路线还须自行完成桌面端连接，并在 `completedSteps` 中增加 `extensionConnect`；Chrome 出现本地网络访问提示时，能否独立处理属于本步骤的观察范围。
3. `download`：等待任务完成。
4. `open`：从应用打开成品或所在文件夹，并确认视频可播放。

四步均未获得提示时，填写 `completedWithoutGuidance: true`、完整的 `completedSteps`，并将 `blockedStep` 设为 `null`。任何一步需要观察员提示时，填写 `false`，将首次受阻步骤写入 `blockedStep`，并用一句话记录原因。五人中至少四人无指导完成才达标。

## 双平台安装包人工回归

macOS Apple Silicon 和 Windows x64 各由人工在真实系统上完成以下检查：

Windows x64 完成 `scripts/build_windows_nsis.ps1` 后，先运行以下命令，把实际 NSIS 的大小和 SHA-256 写入候选清单：

```powershell
node scripts/record_v031_candidate_artifact.mjs --manifest=docs/acceptance/v0.3.1-candidate-artifacts.json --target=windows-x64 --artifact=desktop/release/Downany-0.3.1-win-x64.exe
```

- `firstInstall`：首次安装、启动和首条下载正常。
- `upgradeFrom030`：在 v0.3.0 上直接覆盖安装 v0.3.1 后可启动。
- `settingsPreserved`：覆盖升级前的下载目录、画质等设置仍存在。
- `queuePreserved`：升级前的已完成、等待或暂停任务仍存在。
- `pauseResume`：暂停任务后退出应用，再次启动可以继续并完成。
- `playback`：下载成品可以完整播放。
- `noOverwrite`：重复下载同名内容不会改写已有文件。

每项只有在实际操作并观察到结果后才能填写 `true`。全部完成后将 `manual` 改为 `true`，填写时间和一句简短说明。

## Windows 真实网站矩阵

在 Windows x64 验收机上安装 Chrome，并用有权访问样本的账号保持登录。执行器可直接读取本机登录状态，无需导出或传递 Cookie 文件：

```powershell
node scripts/run_v031_reliability_matrix.mjs `
  --executable=<候选包展开目录中的 Downany.exe 绝对路径> `
  --candidate-artifact=<NSIS 安装包绝对路径> `
  --playwright-module=<Playwright 模块绝对路径> `
  --matrix=<v0.3.1-reliability-matrix.json 绝对路径> `
  --results=<合并结果 JSON 绝对路径> `
  --target=windows-x64 `
  --expected-version=0.3.1 `
  --cookies-from-browser=chrome:Default
```

样本地址仍通过矩阵定义的 `DOWNANY_*` 环境变量注入。命令和结果文件不写入地址、账号、Cookie、Token、浏览器配置路径或原始错误；需要续跑时增加 `--case=<用例 ID>`。

## 判定

在仓库根目录运行：

```bash
node scripts/evaluate_v031_manual_acceptance.mjs docs/acceptance/v0.3.1-manual-acceptance-results.json
```

只有输出中的 `passed` 为 `true` 才表示真人首次使用和双平台人工验收同时达到发布门槛。模板中的空项、自动化记录、候选包哈希不一致、没有真实扩展路线、少于四人无指导完成或任一平台检查缺失都会判定失败。
