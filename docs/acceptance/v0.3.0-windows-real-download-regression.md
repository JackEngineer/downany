## 样本与判定标准

采用 [MDN 的 flower.mp4](https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4)，来源项目使用 [CC0 1.0](https://github.com/mdn/interactive-examples/blob/main/LICENSE)。实测成品为 5.055 秒、960×540 H.264 视频和双声道 48 kHz AAC 音频。

每个成功下载必须同时满足：

- 使用真实输入框或扩展“下载选中”按钮入队，不直接调用入队接口冒充 UI 操作。
- 同一任务达到 `completed`、100%，真实文件位于隔离输出目录，任务下载字节和总字节均等于文件大小。
- 安装包内 ffprobe 验证视频、音频和时长；安装包内 FFmpeg 完整解码两条流并生成 SHA-256。
- 桌面列表显示“已完成”，保存实际窗口截图。扩展入队会切到“进行中”，因此通过真实“全部”筛选按钮查看完成状态。
- 恢复场景与公开下载源的完整解码 SHA-256 一致：`a4063e6466861883b9b3a460c20a8dba6034953f0f5a9f49dd58bd4f57c75f3f`。

文件级 SHA-256 可以因任务标题、来源等嵌入元数据不同而变化，不能据此断定音视频损坏。恢复场景额外核对解码哈希及先前完成文件不变。

## 夹具修复与门禁自检

`tests/core/test_download_manager.py` 原夹具写入的是伪媒体，但漏掉了 `ensure_local_thumbnail` 隔离，因而可能进入真实 FFmpeg 抽帧并超过原有 3 秒任务等待。新增回归先确定性触发伪媒体进入真实抽帧的断言失败，再在该文件既有 autouse 夹具中替换缩略图依赖。没有延长原测试超时，没有改变产品抽帧逻辑；该文件 56 项测试通过。

门禁默认 `--suite=all`，必须覆盖五项真实场景；缺失或重复证据均失败。显式选择 `public-direct`、`public-extension` 或 `recovery` 只记为 diagnostic，不冒充完整门禁。

启动版本不符的负向检查也实际执行过：以预期 `0.3.99` 启动实际 0.3.0，正确退出 1，并留下统一失败报告、stderr、清理结果和前后指纹。审计读取失败或超限也会记录失败，不再跳过报告。

## 隔离与未覆盖边界

- 应用数据、下载文件、Electron profile、测试浏览器 profile 均位于脚本新建 TEMP 根；关闭的仅为本次脚本持有的应用、浏览器和故障服务。
- 日常 Downany 数据只做前后只读指纹审计，不载入测试应用，不把配置内容写入报告。审计限额：10000 个文件、单文件 64 MiB、总计 256 MiB；无法完成审计则失败。
- 应用、ASAR、Sidecar、ffmpeg、ffprobe 五个关键安装文件做前后指纹核对；不把五文件核对描述成整台机器快照。
- 外网样本沿用可用网络环境。只有本机故障场景使用隔离配置中“已填写但关闭”的代理及清理后的子进程代理环境，避免把 loopback 请求转发到系统代理；系统及日常应用代理不变。
- 扩展使用未改动的 popup 文档在独立后台测试标签页操作，活动标签页仍为真实媒体页。证明扩展识别、选中、桥接和下载，不声称验证原生浏览器工具栏弹窗的定位/开关。
- 公开样本不是全站兼容矩阵；未测试登录、付费/受限资源、真实 Telegram 发送、物理系统重启或 Mac。

## 保留的失败与诊断记录

- W3C Bunny 样本被网站 Cloudflare 校验拒绝（HTTP 403），未尝试绕过限制；改用 MDN CC0 样本。
- 初版 UI 自动化忽略“进行中”筛选，以及候选晚到时未自动选中，已改为真实点击筛选和复选框；未因此修改产品行为。
- 初版本机故障请求被系统代理转发并收到 502；通过独立测试配置和子进程环境排除代理干扰，HTTP 404/206/主动断流均由故障服务日志证明。
- 并发运行额外旧包复验时曾遇到旧 Sidecar 30 秒握手超时，日志为空；当时机器约 8 GiB 内存仅余约 0.5 GiB。原失败目录 `downany-packaged-queue-fbfuykvg` 保留；同一程序、同一超时的串行五轮复验通过。不把资源压力推测当成已证实根因，也不把一次串行通过外推为所有低内存情况均可靠。
