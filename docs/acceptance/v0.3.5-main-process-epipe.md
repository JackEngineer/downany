# 0.3.5 Mac 主进程 EPIPE 修复

本轮基线为本地 `94d3b00`、实际安装桌面 / Sidecar 0.3.4，初始工作区干净。桌面与 Sidecar 升为 0.3.5，扩展保持 0.9.3；仅本地 Mac 修复，未推送、发布或操作 Windows。

## 根因与修复

已通过受支持的 Library 下载流程读取并实际查看用户附件像素。截图是主进程 `Uncaught Exception: Error: write EPIPE`，栈位置为安装包 `dist-electron/main.js:59:3810`。从实际 0.3.4 app.asar 提取对应位置，确认为 Sidecar `log` 事件处理器直接调用 `process.stderr.write`。运行进程的 stdout / stderr Unix 管道均无接收端，下载服务和桥仍连接。启动器或调试会话断开后，继续转发日志触发异步管道异常，不能由 Sidecar stdin 的已有错误监听覆盖；此次错误不等于网站下载或登录失败。

新增输出流保护，在任何主进程日志之前监听 stdout / stderr。仅处理 `EPIPE` 与 `ERR_STREAM_DESTROYED`，关闭后停止后续 stderr 写入；其他错误仍抛出。全部 Main 日志转发采用同一安全写入入口，没有添加全局未捕获异常吞噬器，也未更改下载、登录或任务状态合同。接收端消失后无法继续向该输出流记录日志，这是失去输出接收端的限制；应用服务不因此中断。
