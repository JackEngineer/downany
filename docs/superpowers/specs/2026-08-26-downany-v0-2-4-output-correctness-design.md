# Downany v0.2.4 成品正确性设计

**状态：** 架构方向已批准，书面规格待用户复核

**日期：** 2026-08-26

**实现分支：** `fix/v0.2.4-output-correctness`

**上游设计：** `docs/superpowers/specs/2026-08-26-downany-v0-3-staged-upgrade-design.md`

## 1. 目标

v0.2.4 把“下载完成”从一次 yt-dlp 调用没有抛错，升级为可验证的成品合同：用户目录中的主文件真实存在、可被 ffprobe 读取、媒体类型和容器符合选择；请求的字幕、封面、标题与章节在来源提供时按产品语义生成；播放列表目录和文件名安全、稳定且不会把另一条内容误认成已下载。

本版本覆盖单条内容与播放列表的完整落盘链路：

1. 设置转换为明确的 yt-dlp Python API 选项和后处理器。
2. 下载及后处理先发生在任务专属暂存区。
3. 暂存成品通过验证后，以安全名称提交到用户目录。
4. 最终文件再次通过存在性检查后，任务才进入 `completed`。
5. 播放列表分组、最终路径和任务状态重启后仍可恢复并打开。

## 2. 已确认的现状问题

### 2.1 后处理设置没有形成真实管线

当前 `download_manager.py` 向 yt-dlp Python API 传入 `embedthumbnail`、`embedmetadata`、`embedchapters`、`embedsubtitles`、`download_sections` 和 `sponsorblock_remove` 等 CLI 风格字段。直接构造 `yt_dlp.YoutubeDL` 时，这些字段不会像 CLI 入口那样自动翻译成后处理器；运行时的后处理队列为空。现有单元测试只断言字典中存在这些字段，因而会把无效配置判为通过。

### 2.2 发布资源缺少 ffprobe

Windows 下载脚本从包含 `ffmpeg.exe` 与 `ffprobe.exe` 的固定压缩包中只提取前者；macOS 源码构建显式使用 `--disable-ffprobe`。封面流检查、章节时长处理和最终媒体验证均需要 ffprobe，因此“只带 ffmpeg”不能满足成品合同。

### 2.3 完成状态没有验证成品

`Downloader` 在无法确认真实文件时仍可能返回候选字符串，`DownloadManager` 随后直接把任务标为完成。进度钩子还可能留下合并前分片路径。当前没有“文件存在、非空、可探测、位于下载根目录内”的统一门槛。

### 2.4 命名与目录存在安全和正确性缺口

- Windows 上的模板校验只按 `os.sep` 拆分，`../%(title)s.%(ext)s` 可以绕过检查并逃离设定目录。
- `CON`、`AUX`、`LPT1` 等 Windows 保留名和结尾的点、空格没有处理。
- 页面任务只使用标题作为默认名称。yt-dlp API 默认不覆盖已有成品，两个不同链接同名时，后一个任务可能复用前一个文件并被判成功。
- 自定义模板在普通页面、直链和播放列表之间优先级不一致。
- 播放列表文件夹仅使用列表标题，同名列表和重复添加可能互相污染。

### 2.5 播放列表只有分层单测，没有真实闭环

列表解析、分组字段持久化和界面聚合分别有测试，但还没有“真实解析 → 选集 → 下载 → 重启 → 恢复分组 → 打开成品”的证据。整组暂停、恢复和重试的界面实现还会吞掉单项请求错误；该状态机问题归入 v0.2.5，本版本只保证选集、分组目录、分组删除、重启恢复和成品打开。

## 3. 范围

### 3.1 本版本包含

- 视频原格式、转换为 MP4、提取 MP3 三类输出。
- 标题、常规元数据、来源章节和封面的写入。
- 不下载字幕、保存独立字幕、写入视频、写入视频并保留独立字幕四种语义。
- Windows 与 macOS 的 ffmpeg/ffprobe 成对发现、构建、打包和诊断。
- 跨平台安全文件名、播放列表子目录、总路径预算和稳定防冲突标识。
- 任务专属暂存、媒体验证、成品提交和完成状态门槛。
- YouTube 播放列表、Bilibili 多 P/合集和一个普通站点列表的真实验收。
- 播放列表分组持久化、应用重启恢复、分组删除和打开文件验收。

### 3.2 本版本不包含

- 队列重排、整组暂停/恢复/重试的一致性改造；这些属于 v0.2.5。
- SponsorBlock、片段裁剪和任意新后处理步骤。v0.2.4 隐藏当前没有真实实现保证的两个设置入口，但保留旧配置字段，不删除用户配置。
- 对任意网站任意列表形态作普遍承诺。自动识别范围只覆盖本规格列出的 URL 形态和真实样本。
- 自动替换、签名、公证或公开发布。合并、推送、打标签和 Release 仍需单独授权。
- 迁移或重命名用户已经下载的历史文件。

## 4. 核心完成合同

任务只有同时满足以下条件才可进入 `completed`：

1. yt-dlp 返回结构化下载结果，而不是仅返回进度钩子中的候选路径。
2. 主成品是存在的普通文件，大小大于零。
3. 主成品的规范化绝对路径位于任务的下载根目录内。
4. ffprobe 能在限定时间内解析 JSON，并至少发现预期媒体流：视频任务必须有视频流，MP3 任务必须有音频流。
5. 最终容器属于输出方案允许的集合。
6. 当来源实际提供了请求的字幕、封面或章节时，对应的成品特征验证通过。
7. 所有需要保留的独立字幕均已与主文件一起提交到最终目录。
8. 自定义脚本执行后再次通过完整媒体验证；脚本失败但主文件仍通过验证时，下载成品保持完成，脚本结果单独提示。脚本删除、移动或破坏主文件时，任务不得显示完成。

来源没有提供封面、章节或所选语言字幕，不视为下载失败。界面文案明确使用“来源提供时写入”，不得显示并不存在的成功承诺。任务模型新增可选 `completion_note`：它只保存产品化结果，例如“未找到所选语言字幕”或“视频已下载，后处理脚本未完成”，与失败状态分开，并随队列持久化和重启恢复；原始工具输出不得写入该字段。

## 5. 架构

### 5.1 输出方案编译器

新增 `src/core/output_contract.py`，把 `DownloadTask` 与 `DownloadOptions` 编译成不可变的 `OutputPlan`。该模块只负责产品语义，不执行网络或文件操作。

`OutputPlan` 至少包含：

- `media_kind`：`video` 或 `audio`。
- `allowed_containers`：最终允许的容器集合。
- `subtitle_mode`：`none`、`external`、`embedded` 或 `both`。
- `ydl_options`：可直接交给 `yt_dlp.YoutubeDL` 的 API 参数。
- `postprocessors`：按执行顺序排列的显式后处理器。
- `final_leaf_template`：只描述最终叶子文件名，不包含用户可控目录。
- `playlist_folder`：由可信代码生成的可选子目录。
- `requires_ffmpeg` 与 `requires_ffprobe`。

`DownloadManager` 不再逐项拼接嵌入、字幕和命名选项，只负责取得工具链、调用编译器、启动下载、验证和提交。最终叶子候选在 `YoutubeDL` 上下文关闭前使用 `evaluate_outtmpl(final_leaf_template, info, sanitize=True)` 渲染，使模板继续遵循固定版本 yt-dlp 的字段规则，同时不会被 yt-dlp 的 `paths.home` 再次拼入暂存目录。

### 5.2 结构化下载结果

`src/core/downloader.py` 返回 `DownloadResult`，替代仅返回字符串的合同。结果包含：

- yt-dlp 后处理后的主文件路径。
- 需要保留的独立字幕路径及语言、扩展名。
- 后处理后的 info 字典。
- 使用最终模板渲染出的叶子名称候选。
- 实际下载是否发生，以及 yt-dlp 报告的可用字幕、封面和章节事实。

主路径只从后处理完成后的 `info["filepath"]` 和真实存在的文件中取得；合并前的 `requested_downloads[*].filepath` 只能用于诊断，不能成为最终成品。

### 5.3 任务专属暂存区

yt-dlp 的媒体、分片、字幕和封面全部写入 `temp_dir/<task_id>/` 任务专属暂存目录，不直接写入用户最终目录。目录由应用控制并包含任务 ID；用户标题、URL 或模板不得参与暂存目录路径。

成功流程为：

```text
OutputPlan
  → yt-dlp 下载与显式后处理
  → DownloadResult
  → 暂存成品 ffprobe 验证
  → 安全最终路径规划
  → 同目录临时名写入/移动
  → 原子替换为最终名
  → 最终存在性与大小检查
  → completed
```

验证失败时，用户目录不出现新的主成品。任务专属暂存内容属于应用内部临时数据，可以安全清理；不会删除或覆盖用户目录中原有文件。

### 5.4 安全成品提交器

新增 `src/core/output_paths.py` 与 `src/core/output_commit.py`：

- `output_paths.py` 负责模板校验、安全组件、唯一标识、路径预算和根目录约束。
- `output_commit.py` 负责把通过验证的主文件与独立字幕作为一个成品包提交。

跨卷时先复制到最终目录中的任务专属隐藏临时名，校验大小并刷新文件；同卷时也先得到同目录隐藏临时名。提交优先使用不会覆盖既有目标的原子硬链接，再删除临时名；文件系统不支持硬链接时，使用平台的原子 no-replace rename 能力发布已完整写入的隐藏文件。最终可见路径绝不作为边复制边增长的目标；如果当前平台或文件系统不能提供经验证的原子不覆盖发布，则安全失败并保留隐藏暂存供受控清理。目标一旦存在就重新选择数字后缀。每个下载根目录使用进程内提交锁，提交器记录本次独占创建的全部目标；任一独立字幕或主文件提交失败时，只回滚这些任务自建目标。主文件最后提交，使“主文件可见”尽量代表整组成品已经就绪。任何平台都不得用会覆盖未知目标的 `os.replace` 作为冲突处理。

任何步骤失败都不得覆盖既有目标。已经复制的任务专属临时文件可清理，原暂存成品保留到本次失败处理结束。

### 5.5 媒体验证器

新增 `src/core/media_verifier.py`。验证器通过参数数组调用解析出的 ffprobe 绝对路径，不使用 shell。固定参数为：

```text
-v error -print_format json -show_format -show_streams -show_chapters
```

验证结果是结构化 `MediaVerification`，包含容器、流类型、字幕语言、封面流/附件、标题标签、章节数量和安全的产品提示。单次 ffprobe 最长运行 15 秒，stdout/stderr 各最多保留 1 MiB 供解析和受控日志使用。原始 ffprobe 输出、本地绝对路径和媒体 URL 不进入普通用户界面。

### 5.6 历史记录与下游发送交接

Telegram 等下游消费者只能接收最终验证通过的 `file_path`。没有自定义脚本时，顺序为“提交成品 → 最终验证 → 写历史/队列 → `mark_ready` → 发出 `task_completed`”。

有自定义脚本时，为兼容现有持久化处理租约，顺序固定为：

1. 基础成品提交并通过验证后，写入不对 Renderer 发完成事件的历史记录。
2. 以 `postprocess:<task_id>` 登记 `processing` 租约。
3. 在最终主文件上执行脚本，并重新运行完整媒体验证。
4. 脚本成功且文件有效时更新最终历史/队列、调用 `mark_ready`，再发出一次 `task_completed`。
5. 脚本返回失败但文件仍有效时，任务保持完成并写入 `completion_note`；调用 `mark_processing_failed`，不得自动发送，等待用户确认后续动作。
6. 脚本使文件缺失或无效时，任务进入 `failed`，写入 `output_verification_failed`，调用 `mark_processing_failed`，且绝不发出 `task_completed`。

整个流程对 Renderer 只公布一次最终任务状态，不允许先短暂显示完成再回退为失败。

## 6. yt-dlp 输出与后处理规则

### 6.1 视频容器

默认视频优先选择 MP4 视频流与 M4A 音频流；来源没有兼容组合时允许 MKV 回退，不为追求扩展名而强制转码。设置为“转换为 MP4”时，最终容器必须是 MP4，必要时使用 `FFmpegVideoConvertor`。

| 用户选择 | 最终容器 | 转码 | 备注 |
| --- | --- | --- | --- |
| 原格式/最佳 | MP4 优先，MKV 回退 | 默认不转码 | 保留来源质量，兼容封面与字幕 |
| 转换为 MP4 | MP4 | 必要时转码 | 转换先于字幕、元数据和封面写入 |
| 提取 MP3 | MP3 | 音频提取 | 不存在视频内嵌字幕流 |

输出方案显式设置格式选择与 `merge_output_format`，不再依赖 yt-dlp 在不同站点上的偶然默认结果。

### 6.2 元数据、章节与封面

`embed_metadata=true` 的产品含义改为“来源提供时写入标题、封面和章节”。编译器显式加入：

1. `FFmpegMetadata`，参数为 `add_metadata=true`、`add_chapters=true`、`add_infojson=false`。
2. `EmbedThumbnail`，且临时封面在成功写入后删除，不在最终目录额外保留图片。

转换或音频提取必须先完成，元数据随后写入最终容器，封面最后写入。没有封面或章节的来源仍可完成；来源有对应数据但后处理或验证失败时，任务失败为成品错误。

### 6.3 字幕语义

界面用一个四选一控件替代两个容易冲突的复选框，但继续映射现有字段，避免配置迁移：

| 界面选项 | `download_subtitles` | `embed_subs` | 行为 |
| --- | ---: | ---: | --- |
| 不下载字幕 | false | false | 不请求字幕 |
| 保存独立字幕 | true | false | 保留字幕文件 |
| 写入视频 | false | true | 下载字幕用于写入，成功后不保留独立文件 |
| 写入视频并保留独立字幕 | true | true | 写入视频并保留字幕文件 |

`subtitle_langs` 只选择语言，不会自行开启字幕。字幕开启后同时允许作者字幕与自动字幕；同一语言同时存在时，yt-dlp 优先使用作者字幕。语言留空时不再声称“跟随站点默认”：界面文案为“留空则自动选择一个可用字幕”，并固定遵循当前依赖版本的顺序：英文作者字幕、英文自动字幕、其他作者字幕、其他自动字幕，选中第一个可用语言。显式后处理器使用 `FFmpegEmbedSubtitle`；`already_have_subtitle` 只在需要保留独立字幕时为真。

MP3 不支持内嵌字幕。仅音频任务遇到“写入视频”时改为保存独立字幕，并在设置与确认界面用用户语言说明这一结果；完成卡片通过 `completion_note` 保留该说明，不能静默声称已经内嵌。

### 6.4 暂不提供的处理项

`download_sections` 与 `sponsorblock_remove` 继续保留在配置读写和队列兼容层，但从设置界面隐藏，不再传给 yt-dlp。v0.2.4 不展示没有可靠实现和验收的功能。

## 7. 文件名、目录和冲突规则

### 7.1 模板是叶子文件名

“文件名模板”只允许生成一个叶子文件名。校验同时拒绝 `/`、`\`、驱动器前缀、UNC 前缀、绝对路径、`.`、`..`、NUL 和控制字符。模板必须包含 `%(ext)s`，占位符继续使用白名单。

最终路径在提交前执行规范化绝对路径检查：

```text
os.path.commonpath([download_root, final_path]) == download_root
```

比较按当前平台的路径大小写规则执行。下载根目录本身无效或过长时，在网络请求前给出可执行的设置错误。

### 7.2 跨平台安全组件

标题、列表名和模板渲染值统一进行 Unicode NFC 规范化，并处理：

- Windows 非法字符与 ASCII 控制字符。
- 结尾的点和空格。
- `CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`，不区分大小写且包含带扩展名形式。
- 空名称与仅由点组成的名称。
- 单组件最多 120 个 UTF-16 代码单元，截断时保留扩展名、来源键和数字冲突后缀。
- Windows 最终绝对路径最多 240 个 UTF-16 代码单元；下载根目录导致叶子名称可用预算少于 40 个代码单元时，在下载前失败。

跨平台使用同一规则，使 macOS 生成的列表目录也能安全复制到 Windows。名称截断保留扩展名和防冲突后缀。

### 7.3 稳定防冲突标识

默认页面文件名为：

```text
标题 [extractor-id].ext
```

直链缺少可靠 extractor ID 时使用规范化 URL 的短 SHA-256：

```text
捕获标题 [urlhash8].ext
```

编译器为页面生成 `extractor-id` 形式的 `source_key`，为直链生成 `urlhash8`。自定义模板只有同时包含 `%(extractor)s` 和 `%(id)s` 时才视为已经表达页面来源键；否则在扩展名前自动追加 `source_key`。该后缀属于成品安全合同，不能被模板关闭。相同来源得到相同基础名称，不同链接同名时得到不同基础名称。

直链缺少模板字段时，`title` 使用捕获到的任务标题，`ext` 使用实际容器，其余不可获得字段使用安全的 `unknown`，不会回退为 URL 片段或路径。

目标已经存在时一律不覆盖也不复用，使用 ` (2)`、` (3)` 等后缀提交新成品。只有同一持久化任务在重启恢复时，才可以继续使用它已经记录且重新验证通过的 `file_path`；新建任务不得把既有文件报告为本次成功。

### 7.4 播放列表目录

播放列表最终结构为：

```text
下载目录/
  安全列表名 [group8]/
    001 - 标题 [extractor-id].ext
    001 - 标题 [extractor-id].zh-Hans.vtt
```

`group8` 来自已持久化 `group_id`，因此重启和恢复保持不变；同名列表的不同添加批次不会共享目录。列表序号由 `playlist_index` 提供，缺失时按解析顺序补齐。

自定义模板只控制叶子名称主体；播放列表目录、序号前缀和稳定标识始终由产品控制。

## 8. ffmpeg/ffprobe 工具链

`src/sidecar/bin_paths.py` 增加 `resolve_ffprobe_path`，并提供结构化 ffmpeg/ffprobe 配对结果。打包态和仓库资源必须来自同一目录，yt-dlp 的 `ffmpeg_location` 指向该目录；系统 PATH 回退允许两个绝对路径位于不同目录，此时不覆盖 `ffmpeg_location`，由 PATH 供 yt-dlp 发现，媒体验证器仍使用解析出的 ffprobe 绝对路径。

发现顺序保持现有约定：

1. `DOWNANY_BIN_DIR`。
2. 打包态 `resources/bin`。
3. 开发态仓库 `desktop/resources/bin` 或 `bin`。
4. 系统 PATH；只有 ffmpeg 与 ffprobe 同时可用时才构成完整工具链。

打包变更：

- Windows 的 PowerShell 与 shell 下载脚本从同一固定压缩包提取 `ffmpeg.exe` 和 `ffprobe.exe`。
- macOS 构建移除 `--disable-ffprobe`，安装并记录两个二进制的校验值。
- Windows NSIS、macOS DMG 和 CI 前置检查同时要求两者存在且能运行。
- Electron `extraResources` 已打包整个 `resources/bin`，无需新增第二套复制规则。
- 诊断信息增加 `ffprobe_available` 与主版本号，不暴露本地路径。

默认 `embed_metadata=true`，因此正式包缺少任一工具时属于安装不完整，任务在下载前失败并给出“重新安装或导出诊断”的动作，不退回到不可验证的静默下载。

## 9. 播放列表数据流

### 9.1 解析与选集

Renderer 与 Sidecar 继续共享“先展开、再为每个条目建立单任务、单任务保持 `noplaylist=true`”的模型。v0.2.4 收口两端识别用例：

- YouTube `list` 参数和 `/playlist`。
- Bilibili `/video/` 页面通过一次允许列表的解析判断单 P 或多 P，并覆盖 `p`、合集和收藏形态。
- 通用 `/playlist`、`/series/`、`/collection/`、`/lists/`。

确认面板返回的条目事实优先于 URL 粗判。已经带有 `group_id` 与 `playlist_index` 的条目不得被 Sidecar 再次展开。

### 9.2 持久化与重启

`group_id`、`group_title`、`playlist_index`、任务状态和最终 `file_path` 继续写入 `QueueStore`；新增的 `completion_note` 也必须持久化。新增集成测试必须使用同一 SQLite 文件重建 `DownloadManager`，证明：

- 分组字段保持不变。
- 下载中的任务降级为暂停，已完成任务保持完成。
- Renderer 快照重新聚合为同一列表组。
- 已完成子项仍能打开文件和在文件夹中显示。

分组折叠状态仍是本次 UI 会话状态，不作为持久化数据。

## 10. 错误处理

新增三个稳定下载错误码：

- `output_path_invalid`：模板、名称、根目录或最终路径不安全。
- `media_tools_missing`：需要的 ffmpeg/ffprobe 配对不存在或不可执行。
- `output_verification_failed`：下载调用返回，但成品缺失、不可探测、流类型/容器错误，或来源提供的请求特征没有写入。

用户界面只显示对象、状态和下一步：

- 路径问题：打开下载设置。
- 工具缺失：重新安装或导出诊断。
- 成品验证失败：保留原有文件，允许在确认后重试，并提供打开诊断目录。

原始 ffmpeg/ffprobe 输出、命令行、URL、Cookie、Token 和本地绝对路径仅进入受控日志，不进入普通错误卡片。

## 11. 测试与验收

### 11.1 自动化合同测试

必须覆盖：

- 四种字幕模式到 yt-dlp 参数和显式后处理器的映射，以及语言留空时的单语言自动选择顺序。
- MP4、MKV 回退和 MP3 的后处理顺序与允许容器。
- 有/无封面、章节、字幕时的验证期望。
- `/` 与 `\` 路径穿越、绝对路径、UNC、Windows 保留名、结尾点/空格、Unicode、超长路径。
- 页面同名不同 ID、直链同名不同 URL、重复 URL重试和现有无效目标。
- 播放列表目录、序号、独立字幕改名和成品包提交。
- 下载返回候选路径但文件不存在时不得完成。
- ffprobe 返回无效 JSON、超时、缺少视频/音频流或容器不匹配时不得完成。
- ffmpeg/ffprobe 在环境变量、开发态和打包态的成对发现。
- 同一数据库上的播放列表重启恢复及 Renderer 分组。
- 设置界面四种字幕文案和隐藏未实现处理项。

### 11.2 确定性本地媒体测试

测试脚本使用受控的 ffmpeg/ffprobe 生成短小本地样本，至少包括：

- 带音视频流的 MP4。
- 带标题、封面、章节和字幕流的 MP4。
- MKV 回退样本。
- 带标题与封面的 MP3。
- 独立字幕成品包。

这些测试验证真实媒体结构，不以“选项字典里出现某个键”代替后处理结果。

### 11.3 打包门槛

Windows NSIS 和 macOS DMG 的打包 smoke 必须证明：

- Sidecar 可以启动并完成握手。
- 打包资源中的 ffmpeg 与 ffprobe 都存在、可执行且来自预期目录。
- 使用打包工具链生成并探测一个短样本。
- 成品文件位于设定目录，应用的打开文件与在文件夹中显示动作可用。

### 11.4 真实可见验收

每个平台分别记录以下闭环证据：

1. 单条公开视频：下载、元数据/封面检查、系统播放器打开。
2. YouTube 播放列表：选集、独立子目录、重启恢复、打开子项。
3. Bilibili 多 P/合集：条目顺序、中文名称、重启恢复。
4. 一个普通站点列表：解析、分组和至少两个成品。
5. 同名不同内容、非法字符标题、长标题和自定义模板。
6. 外置字幕、内嵌字幕、两者并存和来源无所选字幕。
7. MP4、MKV 回退和 MP3 在至少一个常见系统播放器中打开。

真实站点在验收日不可用时可以替换为同类型公开样本，但必须记录替换原因、日期和实际结果。自动化通过不能代替这组可见验收。
