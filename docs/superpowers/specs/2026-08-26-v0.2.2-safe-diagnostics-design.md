# v0.2.2 安全诊断包设计

- 日期：2026-08-26
- 所属版本：v0.2.2（安装与首次使用可靠）
- 分支：`fix/v0.2.2-safe-diagnostics`
- 状态：采用

## 1. 用户结果

用户在下载失败后可以导出一个真正可用于确认版本、运行环境和失败类型的诊断包，同时不把下载链接、内容标题、原始错误正文、日志正文、Cookie、Token 或本机绝对路径带入压缩包。

设置页应明确说明诊断包包含什么、不包含什么，并继续显示导出后的本机保存位置。

## 2. 当前问题

当前 `src/sidecar/diagnostics.py` 会：

- 把最近日志文件原样复制进压缩包；
- 把失败任务的 URL、标题和原始 `error_message` 写入 JSON；
- 把 yt-dlp、ffmpeg 和 Python 可执行文件的绝对路径写入环境信息；
- 在版本探测失败时把包含本机路径的异常文本写入环境信息。

这些内容无法满足分阶段升级设计中“Cookie、Token、本地绝对路径和未脱敏响应不得进入诊断包”的约束。仅增加若干正则替换也不能证明任意日志正文和任意第三方响应都已脱敏。

## 3. 方案比较

### 方案 A：原始内容加正则脱敏

保留全部日志、URL 和错误正文，匹配常见 Token、查询参数和路径后替换。

优点是支持信息最多；缺点是面对未知凭据格式、任意响应正文和用户内容时无法证明无泄漏，因此不采用。

### 方案 B：结构化摘要与数据最小化（采用）

不把原始日志或失败任务正文写入压缩包，只保留支持排查所需的结构化事实：

- 应用、Python、操作系统、机器架构、yt-dlp 和 ffmpeg 版本；
- yt-dlp 来源与 ffmpeg 是否可用，但不记录可执行文件路径；
- 失败任务总数，以及按稳定 `error_code` 和平台聚合的计数；
- 最近日志文件数、可读文件数、总行数和日志级别计数，不记录文件名或正文；
- 一份固定的隐私说明，列出主动排除的内容。

优点是隐私边界可以通过允许字段和压缩包全文负向扫描证明；缺点是不能直接阅读原始日志。v0.2.2 优先保证用户能够安全导出，后续如需更详细信息，应先把运行日志改造成稳定、结构化、默认脱敏的事件源。

### 方案 C：完全移除诊断包

隐私风险最低，但会破坏 v0.2.2 的首次使用与故障反馈闭环，因此不采用。

## 4. 输出合同

压缩包只包含：

- `environment.json`
- `failed_tasks.json`
- `logs/summary.json`
- `privacy.json`

`environment.json` 不得出现任何 `*_path` 或 `*_executable` 字段。版本命令失败只输出稳定状态，不输出异常正文。

`failed_tasks.json` 使用聚合对象：`total`、`by_error_code`、`by_platform`。空错误码归一为 `unknown`，空平台归一为 `unknown`，输出键按字典序排列，便于稳定比较。

`logs/summary.json` 只统计最近五个普通文件。无法读取的文件计入 `files_seen`，不计入 `files_read`；无法解析级别的行计入 `other`。任何日志文件名和正文都不进入结果。

`privacy.json` 使用固定产品可解释字段，说明诊断包未包含下载链接、内容标题、错误正文、日志正文、Cookie、Token 和本机路径。

Sidecar 返回给当前用户界面的 `path` 仍是本机保存位置；该路径不得写回压缩包。

## 5. 兼容性与失败处理

- `app.exportDiagnostics` 方法名和顶层返回字段 `ok`、`path`、`failed_task_count` 保持兼容。
- 保留 `log_files` 返回字段，但其值改为空列表，避免旧调用方因字段缺失失败；新增 `log_summary` 供后续界面或验收使用。
- 版本探测、日志枚举或单个日志读取失败不能导致整个导出失败。
- 压缩包仍在本机数据目录的 `diagnostics/` 下生成。

## 6. 验收门槛

- 回归测试构造含 Cookie、Authorization、Telegram Bot Token、查询 Token、Windows/macOS 绝对路径、私密标题和原始响应正文的任务与日志。
- 导出后的所有压缩包成员不得包含上述哨兵值，也不得包含原始日志文件。
- 精确断言四个允许成员及其字段合同。
- `tests/sidecar/test_diagnostics.py`、完整 Sidecar 测试、Python 主线测试通过。
- 设置页用户文案准确描述包含与排除内容，相关 Renderer 测试和生产构建通过。
- 变更只形成独立本地提交，不合并、不推送、不打标签、不发布。
