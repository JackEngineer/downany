# 视频下载器 Electron 迁移设计

日期：2026-07-19  
状态：已审阅通过；阶段 0–4 实施完成（发布签名/公证视证书环境而定）

## 1. 背景

当前应用以 Python、PyQt6 和 yt-dlp 为主线，并保留一套 SwiftUI 并行实现。现有下载核心已经支持平台识别、单条与批量下载、队列、暂停恢复、历史、代理、字幕和主题，但界面存在以下系统性问题：

- 搜索与链接下载被拆成两个一级入口；
- 固定指标卡、重复状态和过度卡片化挤压核心工作区；
- 960×640 及字体放大场景下出现内容裁切；
- 任务失败、完成后操作和全局传输状态缺乏可发现性；
- Qt 线程关闭、主题绘制和组件生命周期仍有技术风险。

迁移目标不是把现有 PyQt 页面逐像素搬到 Web，而是在保留成熟下载核心的前提下，重新建立产品结构、交互层级和桌面发布能力。

## 2. 已确认决策

- Electron 成为新的产品主线。
- Python + yt-dlp 继续作为下载核心。
- Electron 与 Python Sidecar 通过标准输入输出上的 JSON Lines 通信。
- PyQt 和 SwiftUI 暂时保留，但停止新增功能。
- 首个可发布版本包含链接下载、队列、历史和设置。
- 站内搜索和应用内预览延后到第二阶段。
- 首版面向 macOS，交付签名、公证的 DMG。
- 产品暂名为“视频下载器”。
- 用户可见文案、配置路径、数据库路径和 Bundle ID 等全部移除 Trae 标识。
- 首次启动自动迁移旧配置与历史数据。
- 下载队列持久化到 SQLite；退出应用时未完成任务转为“已暂停”，重启后可续传，不静默取消。
- 应用本体首版不自动更新，但 yt-dlp 支持应用内独立更新。
- 链接解析可取消、逐条返回结果，并允许跳过解析直接入队。

## 3. 目标与非目标

### 3.1 目标

1. 用户启动应用后可以立即粘贴链接并创建下载。
2. 下载状态、速度、体积、剩余时间和失败原因始终清晰。
3. 960×640 到宽屏窗口均可完整访问所有核心操作。
4. Electron Renderer 不直接访问 Node.js、文件系统或子进程。
5. Python 是下载任务与持久化状态的唯一事实来源。
6. Sidecar 崩溃、协议错误和应用退出均有明确、可恢复的行为。
7. 旧用户数据安全迁移，旧版本仍可回退使用。
8. 发布产物包含可用的 yt-dlp 和 ffmpeg，并通过 macOS 签名与公证。

### 3.2 非目标

- 首版不迁移站内搜索和应用内视频预览。
- 首版不支持 Windows 和 Linux。
- 首版应用本体不自动更新，只预留更新接口；yt-dlp 独立更新不在此限。
- 首版不支持浏览器 Cookie 导入。
- 不在迁移期间重写 yt-dlp 调用、下载状态机或数据库为 Node.js。
- 不删除现有 PyQt 和 SwiftUI 代码。
- 不保留现有界面的页面结构和视觉样式兼容性。

## 4. 产品结构

采用“命令中心”布局：

- **新建任务**：默认入口，支持单条或多条链接解析与确认。
- **下载队列**：查看等待、下载、暂停、失败和完成任务。
- **历史记录**：检索历史、重新下载、打开本地文件。
- **设置**：下载目录、并发、速度、画质、字幕、代理和主题。

宽窗口使用带文字的侧边栏；紧凑窗口折叠为图标导航。设置固定在侧边栏底部。页面不再展示统一的三指标卡，也不再保留重复的全局状态栏。

## 5. 页面与交互设计

### 5.1 新建任务

1. 用户粘贴一个或多个链接。
2. Electron 请求 Sidecar 解析链接，解析遵循代理设置。
3. 界面展示标题、平台、质量、字幕和可选格式。
4. 用户确认后才创建任务。
5. 无效链接与未知链接单独列出，默认不加入队列。
6. 支持将文本或 URL 拖入窗口，走同一解析确认流程。

解析行为约束：

- 批量解析逐条返回结果，界面渐进展示，不等待全部完成；
- 解析可随时取消，取消后 Sidecar 必须真正中断对应的 yt-dlp 调用；
- 单条解析有超时，超时视为解析失败并给出原因；
- 解析失败或用户主动选择时，允许以占位标题“跳过解析直接入队”，任务开始下载后再补全元数据。

页面只保留一个主操作。空输入、格式错误和解析失败使用字段内提示，不使用模态弹窗。

### 5.2 下载队列

每个任务直接展示：

- 标题与平台；
- 状态；
- 进度；
- 已下载体积与总大小；
- 下载速度；
- 剩余时间；
- 当前状态允许的操作。

进行中任务展示暂停和取消；暂停任务展示恢复；失败任务展示简短原因和重试；完成任务突出“打开文件”和“在访达中显示”。低频操作进入上下文菜单。

队列标题区仅在有活跃任务时展示总速度和活跃数量，并提供“全部暂停”“全部恢复”“清除已完成”批量操作。空态提供“新建下载”主动作，不同时显示空表格。

### 5.3 历史记录

- 支持即时搜索和状态筛选。
- 行内或上下文工具栏提供重新下载、打开文件和删除。
- 单选与多选共用一个删除动作，文案根据选择数量变化。
- 清空历史是破坏性操作，必须二次确认。
- 大数据量使用分页或增量加载，不一次创建大量行级组件。

### 5.4 设置

采用稳定表单网格：

- 宽窗口：标签列、弹性控件列、尾部操作列；
- 窄窗口：标签在上、控件在下；
- 页面可纵向滚动；
- 设置即时保存，但必须显示“已保存”“正在保存”或“输入有误”。

启用代理时地址不能为空。下载目录必须验证存在性、可创建性和写权限。首个无效字段获得焦点，并与错误描述建立可访问性关联。

### 5.5 反馈规则

- 成功操作使用非阻塞反馈。
- 带行动按钮的反馈不会在键盘焦点停留时消失。
- 字段错误保留在字段附近。
- 任务错误保留在任务上下文中。
- 只有删除、清空和退出未完成任务等破坏性操作使用确认对话框。
- 系统通知仅在应用位于后台时发送。
- 预览或打开外部页面必须由用户明确触发。

## 6. 系统架构

### 6.1 Electron Renderer

- 使用 React 和 TypeScript。
- 负责页面渲染、路由、表单状态和任务快照展示。
- 不直接读取文件、不启动进程、不访问 Node.js API。
- 通过 Preload 暴露的窄接口调用主进程。

### 6.2 Electron Preload

- 启用 `contextIsolation`。
- 禁用 `nodeIntegration`。
- 暴露版本化、类型安全的应用 API。
- 对参数和返回值做运行时校验。
- 不向 Renderer 暴露任意 IPC 通道或通用命令执行能力。

### 6.3 Electron Main

负责：

- 单实例锁：拒绝第二个实例启动，避免两个 Sidecar 并发写同一配置和数据库；
- 窗口与生命周期，包括窗口尺寸与位置的持久化；
- 原生菜单和快捷键；
- 文件及目录选择；
- 系统通知；
- 在访达中显示文件；
- Sidecar 启动、心跳、重启和优雅退出；
- 协议消息转发与校验；
- 发布环境中的资源路径；
- 自动更新能力预留。

### 6.4 Python Sidecar

负责：

- yt-dlp 与 ffmpeg 调用；
- URL 解析与平台识别；
- 下载队列和状态机；
- 暂停、恢复、取消和重试；
- 配置与历史持久化；
- 任务快照；
- 结构化错误转换；
- 优雅退出。

Sidecar 不依赖 PyQt，不发送 Qt 信号，也不持有任何界面对象。

配置所有权：所有用户可配置项（下载目录、并发、速度、画质、字幕、代理、主题偏好）由 Sidecar 统一持久化到 `config.json`，Electron 通过 `settings.get` / `settings.update` 读写。Electron 只自行持久化纯界面状态（窗口几何）；“跟随系统”主题的实际明暗判定由 Electron 的 `nativeTheme` 完成。

### 6.5 任务持久化

- 下载队列持久化到应用数据目录的 SQLite（与历史同库、独立表）；
- 任务创建、状态变化和删除同步写库，进度百分比可低频写入；
- Sidecar 启动时从数据库恢复队列：处于“下载中”的任务恢复为“已暂停”，等待、暂停、失败、完成状态原样保留；
- 半成品文件保留，恢复下载依赖 yt-dlp 断点续传；
- 崩溃后重启的恢复与正常启动走同一条路径，不依赖崩溃前的内存状态。

### 6.6 yt-dlp 独立更新

- 打包内置一份固定版本的 yt-dlp 作为保底；
- 设置页提供“检查 yt-dlp 更新”，从 yt-dlp 官方发布下载独立可执行文件到应用数据目录；
- 下载后校验完整性并做一次可执行性自检，通过后才切换使用；
- 更新失败或新版本损坏时自动回退到内置版本；
- 更新由用户显式触发，首版不做后台静默更新。

## 7. 通信协议

传输格式为 UTF-8 JSON Lines，每行一条完整消息。标准输出只允许协议消息；诊断日志写入标准错误或日志文件。

### 7.1 消息类型

- `request`：Electron 发起操作，含 `method`；优雅退出通过 `app.shutdown` 请求完成，不设独立消息类型；
- `response`：Sidecar 返回请求结果，通过 `correlationId` 关联请求；
- `event`：Sidecar 主动发布任务变化，含 `event` 名称；
- `hello`：双方交换协议和应用版本。

心跳：Electron Main 每 5 秒发送 `app.ping` 请求，Sidecar 必须在超时内响应；连续 3 次未响应判定 Sidecar 失联，进入 8.2 的崩溃处理流程。

### 7.2 通用字段

每条消息包含 `protocolVersion`、`type`、`timestamp`，以及按类型附加的字段：

- `request`：`id`、`method`、`payload`；
- `response`：`correlationId`、`payload` 或错误对象；
- `event`：`event`、`payload`；
- `hello`：`payload`（协议版本与应用版本）。

错误响应包含稳定错误码、用户可读信息、是否可重试和可选诊断详情。Renderer 不直接展示原始异常堆栈。错误码清单在阶段 1 定义 schema 时一并冻结。

### 7.3 首版能力

- `app.getSnapshot`
- `app.ping`
- `app.shutdown`
- `download.parseUrls`（逐条结果以事件返回）
- `download.cancelParse`
- `download.createTasks`（支持未解析链接直接入队）
- `download.pause` / `download.pauseAll`
- `download.resume` / `download.resumeAll`
- `download.cancel`
- `download.retry`
- `download.remove`
- `download.clearFinished`
- `history.list`（带分页参数：偏移或游标、数量、筛选条件）
- `history.delete`
- `history.clear`
- `settings.get`
- `settings.update`
- `updater.checkYtDlp`
- `updater.updateYtDlp`

事件包括任务新增、状态变化、进度、完成、失败、历史变化、设置变化和 Sidecar 健康状态。

### 7.4 状态一致性

Python 是任务状态唯一事实来源。Renderer 只保存只读快照，不跨进程修改任务对象。

进度事件可以节流，但完成、失败、取消和删除事件不得丢弃。连接恢复后 Electron 必须重新请求完整快照，而不是依赖补发事件推断状态。

## 8. 生命周期与错误恢复

### 8.1 启动

1. Electron Main 启动 Sidecar。
2. 双方完成 `hello` 协商。
3. 协议版本兼容后获取完整快照。
4. Renderer 收到快照后进入可操作状态。

若 Sidecar 无法启动，界面显示明确故障页和日志位置，不提供会失败的下载操作。

### 8.2 Sidecar 崩溃

- Main 记录退出码和最近错误。
- Renderer 冻结写操作并保留最后快照。
- Main 进行有限次数、带退避的重启。
- 重启的 Sidecar 按 6.5 从数据库恢复队列，崩溃时下载中的任务恢复为“已暂停”。
- 重连后重新获取完整快照，覆盖 Renderer 保留的旧快照。
- 连续失败后停止自动重试，提供“重新连接”和“打开日志”。

### 8.3 退出

- Renderer 请求退出。
- Main 向 Sidecar 发送 `app.shutdown`。
- Sidecar 停止接受新任务，中断进行中的下载并把这些任务标记为“已暂停”，保留半成品文件，写入最终状态到数据库后确认退出。退出不取消任何任务。
- Electron 展示退出进度，不在 GUI 主线程无反馈等待。
- 超过总超时时间后，用户可以选择继续等待或强制退出；强制退出后下次启动仍按 6.5 恢复队列。

## 9. 数据与品牌迁移

### 9.1 新标识

- 用户可见名称：`视频下载器`
- Electron `productName`：`Video Downloader`
- Bundle ID：`com.jacklee.videodownloader`
- 应用数据目录：`~/Library/Application Support/VideoDownloader/`
- 配置文件：`~/Library/Application Support/VideoDownloader/config.json`
- 历史数据库：`~/Library/Application Support/VideoDownloader/history.db`
- 日志目录：`~/Library/Logs/VideoDownloader/`
- 全新安装的默认下载目录：`~/Downloads`

发布产物、进程名、协议名和新建文件均不得使用 Trae 标识。

### 9.2 迁移原则

迁移由 Sidecar 执行（它拥有配置和数据库），Electron Main 在首次启动时触发并向用户展示迁移结果。旧设置存于 macOS plist，Python 侧使用 `plistlib` 读取，不引入 Qt 依赖。

- 迁移前创建备份；
- 复制而不是移动旧数据；
- 校验新配置和数据库后再标记成功；
- 迁移过程幂等；
- 失败不破坏旧版本继续运行；
- 不自动删除旧目录；
- 用户可以查看迁移结果与日志。

### 9.3 迁移内容

- `~/Library/Preferences/com.Trae.Downloader.plist` 中的旧设置；
- `~/.trae_downloader/history.db` 中的下载历史；
- 下载目录和默认质量；
- 并发、速度限制、字幕和代理设置；
- 主题偏好。

窗口几何和 PyQt 专属界面状态不迁移。旧版本不持久化活跃下载任务，因此没有队列可迁移，新装用户和迁移用户的队列均从空开始。

- 原生应用菜单；
- `Cmd+N` 聚焦新建任务；

- `Cmd+,` 打开设置；
- `Cmd+W` 关闭窗口；
- Finder 打开与显示文件；

- Dock 徽标展示活跃任务数量；
- 明暗主题实时跟随系统；
- 窗口尺寸和位置持久化；
- 签名、公证和 DMG 分发。

## 11. 安全设计

- Renderer 开启上下文隔离，禁用 Node 集成。
- Preload 只暴露白名单能力。
- 所有 IPC 和 Sidecar 消息做结构校验。
- URL 解析不允许成为任意命令参数拼接入口。
- Sidecar 使用参数数组启动 yt-dlp 和 ffmpeg，不通过 shell 拼接命令。
- 日志隐藏代理凭据等敏感信息。
- 下载路径在写入前规范化并验证。
- 打包资源固定版本并进行完整性校验；yt-dlp 独立更新按 6.6 单独校验。
- ffmpeg 使用 LGPL 构建分发，满足许可合规。
- 不开启本地 HTTP 端口。

## 14. 验收标准

1. 干净环境安装后可以解析链接、创建任务并完成下载。
2. 退出应用时进行中任务转为“已暂停”，重启后队列完整恢复并可续传，无任务被静默取消。
3. Sidecar 崩溃后界面不会显示虚假进度；重连后队列从数据库恢复，下载中任务呈现为“已暂停”。
4. 960×640、默认窗口和宽屏下所有核心操作均可到达。
5. 完整键盘流程无需鼠标即可创建并管理下载。
6. 深浅主题下不存在不可读的状态、按钮或选中态。
7. 首次启动可以幂等迁移旧 Trae 配置与历史。
8. 旧数据迁移失败时不破坏旧版本。
9. 发布产物不包含用户可见或技术标识中的 Trae 字样。
10. `.app`、签名、公证和 DMG 验证全部通过。
11. PyQt 与 SwiftUI 仍可构建或运行，但不承载 Electron 新功能。
12. 第二个应用实例无法启动，不会出现双 Sidecar 并发写数据。
13. yt-dlp 应用内更新成功后生效，损坏或失败时回退内置版本。
14. 批量解析可中途取消，已解析条目保留，未解析条目不残留后台进程。
