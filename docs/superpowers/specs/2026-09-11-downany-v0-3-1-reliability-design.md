# Downany v0.3.1 下载可靠性升级规格

- 日期：2026-09-11
- 版本主题：下载成功与失败恢复
- 基线：公开版 v0.3.0
- 发布原则：三个目标平台分别达标；Mac 与 Windows 候选包均完成验收后才可发布

## 1. 用户结果

首次使用者可以完成第一条下载。下载失败时，界面说明可理解的原因，并直接打开对应的登录状态、网络、下载工具、下载位置或网页识别入口。重试沿用原任务的画质、目录、字幕和后处理选项。

## 2. 交付范围

### 2.1 常用平台可靠性

- YouTube、Bilibili、抖音各 10 条，共 30 条固定场景。
- 每个平台包含普通视频、需要登录的视频、合集和失效内容。
- URL 不提交到仓库。运行人员通过矩阵中的 `urlSource` 环境变量提供已获授权的样本，验收记录只写用例 ID、结果、错误码、成品校验和与时间。
- 可下载样本必须完成下载且成品可完整解码；三个平台分别达到 90%。失效内容不进入成功率分母，但错误码必须与矩阵一致。

### 2.2 失败恢复

- `need_login` / `private`：打开登录状态选择并聚焦控件，同时保留网页识别入口。
- `network` / `geo_blocked`：打开代理设置并聚焦控件。
- `ytdlp_outdated`：打开下载工具检查入口并聚焦控件。
- `output_path_invalid`：打开下载目录并聚焦控件。
- `removed`：不提供无效重试。
- 重试继续使用持久化任务选项，不新建默认配置任务。

### 2.3 首次下载

- 启动后下载目录可用；不可写时在入队前给出操作入口。
- 手动添加、扩展入队和网页识别均给出明确反馈。
- 完成后可以打开成品或在文件夹中显示。
- 5 名从未使用 Downany 的试用者中至少 4 名不经指导完成“安装 → 添加 → 下载 → 打开成品”。

### 2.4 正式安装包回归

- macOS Apple Silicon 和 Windows x64 分别使用最终候选包。
- 两个平台均验证首次安装、从 v0.3.0 覆盖升级、设置与队列保留、暂停恢复、成品播放和已有文件不被覆盖。
- 自动化包测试、人工安装和真人试用分别记录，不能互相替代。

## 3. 发布门槛

1. Python、桌面端、扩展和生产构建全部通过。
2. 30 条矩阵完成；机器评估结果 `passed=true`。
3. 失败恢复操作在中英文界面均可用，提示不暴露 URL、Cookie、Token、文件私有路径或原始异常。
4. 5 人试用达到 4 人成功，失败原因已归档。
5. Mac 与 Windows 最终候选包均有人工记录；升级保留数据，成品可播放。

任一门槛缺少证据时保持候选状态，不打 `v0.3.1` 标签。

## 4. 明确不纳入

- 新增下载平台、主界面视觉重做、Telegram Local Bot API、完整多语言扩展。
- macOS Developer ID、公证和自动替换更新不作为 v0.3.1 的阻塞项，单独进入 v0.4.0 候选范围。
