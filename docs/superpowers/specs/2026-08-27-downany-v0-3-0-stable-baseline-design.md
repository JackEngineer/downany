# Downany v0.3.0 Windows 稳定基线设计

- 日期：2026-08-27。
- 依据：既定分阶段方案 A，以及用户要求自主继续、不要反复确认、不做人工验收、不负责 Mac。
- 类型：已有产品的跨模块收尾，不引入新下载主线或更新安装系统。
- 本轮结果：可追溯、自动化验证的 Windows 本地候选，不代表已安装、已提交或已公开发布。

## 1. 进入事实

v0.2.5 R2 已完成 758 项 Python、410 项桌面测试、真实 v0.2.4 包数据迁移、五轮恢复和 Electron 隔离启动。NSIS SHA-256 为 `ca4f626f04eba3ff392150671449cba073b8cee842dbbccd3fc4b55c545b70c7`。

本阶段独立工作树为 `fix/v0.3.0-stable-baseline`。以 `c7709bcc64035c18cf94efcfc62b40ad088b8f24` 加 v0.2.5 未提交候选构建基线，475 个源码/文档文件逐字节复制、零差异；完整继承清单 SHA-256 为 `a9405057d502381430ca00dab0ed7d5dc98ff62b8a67741aee809d6cfd13952a`。不能把该 HEAD 单独称为候选源码提交。

已观察到的收尾缺口：

1. v0.2.5 新操作已保护快照竞态，但启动/重连、单项操作、手动添加、外部入队仍可直接用旧响应覆盖任务。启动查询与连接事件也可能交错。
2. v0.2.1 tag 已存在；其真实队列表没有运行意图和新的时间字段。需要独立于当前数据模型生成旧格式样本，验证设置、队列、历史与 Telegram 路由保留。
3. 现有中英文目录只覆盖部分导航；队列操作、失败恢复、设置中的更新/诊断仍有固定中文或内部技术说明。语言变更也缺少跨窗口 storage 通知处理。
4. 部分操作错误直接显示原始异常；设置页的更新说明还包含内部库名和文档路径。应改为用户可执行的结果与下一步。
5. 默认 Electron smoke 只隔离数据库，默认下载目录仍来自用户主目录；应将测试输出也纳入隔离配置，且不覆盖已存在配置。

## 2. 方案选择

- 采用：复用 v0.2.5 的请求级快照保护，补齐剩余入口；旧格式 fixture 与当前包各自验证升级；在现有语言机制中统一关键路径；最后形成同源 Windows/扩展产物。
- 不采用全量协议修订号：它可覆盖更广泛的分布式顺序问题，但本轮已定位问题可在客户端请求边界处理，无需改变 JSON Lines 协议。
- 不引入自动替换安装或新迁移框架：现有数据加载已承担向后兼容；先用真实旧格式证实缺口再修复，不新增证书或安装权限依赖。

## 3. 不变量

- 六种公共任务状态、默认单链接语义、输出文件命名/内容、下载与 Telegram 发送解耦均保持。
- 最新完成/移除事件不得被任何旧刷新响应覆盖；断连或组件卸载后的请求不得污染新连接。
- 源码级旧格式迁移与真实旧包升级分别记录，不能相互冒充；所有测试使用临时数据库和输出。
- 用户暂停保持暂停，失败/取消不自动重试，已完成成品与历史事实不变；新字段的默认值和重复打开幂等。
- 中文仍为默认；用户选择 English 后关键路径使用一致语言。标题、站点名、文件路径等用户内容不翻译。
- 错误提示不包含原始异常、URL、Cookie、Token 或内部调用链。导出的诊断包保存位置是用户主动获取的结果，可以展示。
- 不跑 Mac 构建/验收，不修改或清理既有 Mac 实现/工作流/产物；不要求人工安装、窗口操作或系统重启。
- 不提交、合并、推送、打 tag、触发远程 CI、上传、发布、部署网站或删除工作树。

## 4. 收尾范围

### 4.1 请求与连接一致性

- 启动订阅抽成可测试的 `startAppSession`，集中管理 initial query、onState、onEvent、alive/connection generation 与注销。
- `appStore.refreshSnapshot` 继续负责请求期间任务和设置变化。断连或停止会话时失效待返回快照，保留已知任务直到新快照到来。
- 单项操作、创建任务与浏览器入队刷新全部接入同一保护；每个入口都有“请求未返回 → 完成/移除事件 → 旧响应”的测试。
- 所有后台刷新拒绝均有 catch；不把已入队事实错误描述为添加失败。操作本身失败与操作成功后的刷新失败分别处理。
- 设置的初始化响应不得盖过更晚的设置事件；保存响应不得倒退用户正在编辑的更新一版草稿。只针对已经存在的异步流程，不重构全部表单。

### 4.2 旧数据保留

- 由本地 `v0.2.1` tag 源码在隔离目录生成 SQLite schema 与默认配置样本，记录 tag commit、生成方式和内容哈希。
- 将去除个人路径的 SQL/JSON fixture 纳入测试；测试运行不依赖网络、Git tag 存在或旧 Python 包安装。
- 当前 QueueStore、DatabaseManager、JsonConfig 打开旧格式，检查任务 ID/分组/优先级/顺序、内部运行意图默认值、设置未知键、历史成品、Telegram 路由/精确偏移量与发送结果。
- 重复加载、混合任务状态、空可选字段与未知配置键有明确断言；发现真实兼容缺陷时先 RED 再最小修复。
- 包级验证分别使用旧格式 fixture 和真实 v0.2.5 Sidecar 数据；真实下载/退出恢复继续使用本地 HTTP 和已验证媒体工具。

### 4.3 关键路径语言与安全提示

- 统一目录键与插值，不复制多套状态/按钮翻译；同窗口语言切换和另一窗口的 storage 事件都会使已显示组件更新。
- 覆盖：添加/确认、连接失败、任务状态与主操作、失败恢复、分组/全局/排序、设置的语言/保存/下载位置/更新/诊断。
- 任务菜单与关键确认使用相同词汇；既有内容标题、品牌和站点名保留。
- 更新按钮根据结构化状态生成提示，拒绝或未知状态显示安全回退，不直接显示不可信消息。
- 不承诺全部低频界面或原生菜单完成英文翻译；未覆盖范围写入验证记录。

### 4.4 验证与交付

- 修复默认 Electron smoke 输出隔离；只创建缺失的临时配置，不覆盖现有配置或用户数据。
- 复用已存在的媒体/Sidecar/扩展测试，不生成另一套下载引擎替身来代替包验证。
- 先完成代码审查与全量回归，再构建 v0.3.0 onedir Sidecar、Windows NSIS 与扩展 ZIP；扩展版本仍取其 manifest。
- 每个产物记录文件名、大小、SHA-256、签名状态、源码清单与对应测试数据目录；保持 v0.2.5 R2 不变。
- README、路线图、发布说明、扩展说明与官网文字只表达实际能力；本地候选不得被描述为当前公开版本。
