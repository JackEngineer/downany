# Downany 真实媒体横幅还原修复设计

## 背景

当前开发画廊能够接近 `docs/assets/downany-main-window-glass-v1.png`，但真实 Electron 使用现有任务数据后出现明显失真：低质量缩略图被全宽放大、浅色媒体与白色文字冲突、Reading Glass 变成灰色蒙版，顶部输入框还出现原生控件与自定义外壳叠加。

这不是单一 CSS 参数问题。生产 `TaskList` 直接把真实缩略图交给单层全幅背景，所有任务默认使用同一亮度等级；`MediaTaskBanner.tsx` 同时保留旧内联视觉常量，新样式表只能依靠高优先级覆盖它们。开发画廊使用精修位图，因而没有暴露真实媒体质量差异。

本轮以用户提供的真实 Electron 截图为失败基线，以 `docs/assets/downany-main-window-glass-v1.png` 的层级、材质与注意力秩序为目标基线。

## 目标

1. 真实任务在高质量、低质量、竖向、亮色和缺失缩略图下都保持稳定构图。
2. 深色主题呈现目标稿的安静窗口镀铬、局部强玻璃和清晰媒体焦点。
3. 浅色主题保持浅色窗口，但媒体横幅仍是深色阅读表面，不能出现白字压白图。
4. 组件视觉只由语义令牌和样式表控制，React 负责行为与可测的媒体质量、亮度分类。
5. 验收使用真实 Electron、现有任务数据、深浅主题与最小窗口宽度；开发画廊只用于状态覆盖。

## 非目标

- 不用生成图片替换用户任务的真实缩略图。
- 不改变下载、恢复、重命名、菜单或任务状态行为。
- 不把 Reading Glass 扩散到设置、历史、普通列表或整个窗口。
- 不引入新的远程图片服务、运行时依赖或持久化媒体分析服务。
- 不追求目标稿的逐像素复制；必须保留真实数据、系统主题和可访问性约束。

## 方案选择

采用“自适应双层媒体”方案。

- 质量足够的媒体继续作为清晰全幅背景。
- 质量不足或明显竖向的媒体使用同一图片构成两层：全幅暗化模糊环境层，以及右侧受控的清晰焦点层。
- Reading Glass 始终只覆盖左侧文字区，与媒体质量策略解耦。

该方案比继续堆叠遮罩参数更能处理真实低清图片，也比固定右侧小缩略图更接近已确认的媒体横幅方向。

## 媒体分类

媒体分类包含互不替代的两个维度：质量决定图片如何构图，亮度决定 Reading Glass 的染色强度。两者都来自真实图片，不允许开发画廊手工指定。

### 质量

新增纯函数 `classifyArtwork`，输入图片天然尺寸和横幅当前渲染尺寸，输出：

- `standard`：天然宽高均不小于对应渲染尺寸，且图片宽高比不小于 `1.2`。
- `weak`：天然宽或高小于对应渲染尺寸，或者图片宽高比小于 `1.2`。
- `missing`：缩略图为空、加载失败或天然尺寸无效。

分类只决定媒体构图，不改变任务状态与业务数据。窗口尺寸变化时使用最近一次图片天然尺寸重新分类；不得把分类写入 Sidecar 或数据库。

组件使用 `ResizeObserver` 监听横幅尺寸，并复用图片加载时记录的天然尺寸。没有天然尺寸前按 `weak` 渲染，避免首帧先出现低清全幅放大再跳变。

`1.2` 的宽高比分界用于识别会在超宽横幅中产生极端裁切的竖向或近方形图片。尺寸判断使用 CSS 像素对应的 `clientWidth/clientHeight`，避免低分辨率图片被放大到整张横幅。

### 亮度

新增纯函数 `classifyArtworkTone`，输入图片采样后的相对亮度，输出 `dark / medium / light`：

- `dark`：相对亮度小于 `0.24`。
- `medium`：相对亮度位于 `0.24–0.58`。
- `light`：相对亮度大于 `0.58`。

图片加载后，将可见环境层绘制到复用的 `16 × 16` 离屏 Canvas，以线性化 RGB 的平均相对亮度完成一次采样。读取远程图片像素受 CORS 限制时捕获 `SecurityError`，不得影响图片显示；无法采样时使用保守的 `light`，优先保证白色文字对比度。缩略图 URL 变化时重新采样，窗口缩放不重复采样。

## 横幅渲染结构

`MediaTaskBanner` 的媒体层从单张图片调整为：

1. `artwork-ambient`：始终存在的全幅环境层。
2. `artwork-focus`：只在 `weak` 时显示的右侧清晰焦点层。
3. `shade`：全图约 10% 的稳定暗化层。
4. `reading-glass`：左侧阅读玻璃。
5. 内容与操作。
6. 下载中进度线。

### `standard`

- 环境层清晰全幅显示，`object-fit: cover`。
- 不执行额外缩放，不显示右侧焦点层。
- 原图只接受统一轻暗化，不使用全图灰雾。

### `weak`

- 环境层全幅显示并应用约 `22px` 模糊、轻降饱和和约 `0.62` 亮度；通过小幅放大消除模糊边缘。
- 焦点层占横幅右侧约 `48%`，使用 `object-fit: cover`，左缘以 `80px–96px` 羽化进入环境层。
- 焦点层不添加额外高斯模糊；低清像素只出现在较小的受控区域，不再铺满整张横幅。

### `missing`

- 使用现有媒体占位语义，但降低装饰性，只保留暗色中性渐变和平台首字。
- 不显示焦点层。

两张 `<img>` 使用同一 URL。浏览器可以复用已解码资源，不增加网络请求语义。

## Reading Glass

- 覆盖左侧 `58%–60%`。
- 模糊使用 `40px`，饱和度使用 `1.18–1.2`。
- `dark / medium / light` 分别使用约 `0.34 / 0.42 / 0.50` 的深色染色透明度。
- `weak` 在亮度结果上增加约 `0.04`，上限 `0.54`，抵消低清环境层产生的亮斑和色噪声。
- 右缘使用 `104px–112px` 羽化渐隐。
- 玻璃不使用圆角内卡片、不使用整块白色高光，也不覆盖右侧焦点媒体。
- 文字永远使用媒体文字令牌，不根据图片改成黑色。

关闭透明度或浏览器不支持 `backdrop-filter` 时，左侧退化为稳定深色渐变，仍保留相同宽度与羽化，不允许退化成覆盖整张横幅的灰色矩形。

## 主题行为

- 新安装的默认主题改为 `dark`。
- 已有明确保存的 `light / dark / system` 设置继续生效，不做强制迁移。
- 深色主题是视觉基准。
- 浅色主题只改变窗口画布、标题栏、操作栏、筛选栏和普通控件；媒体横幅继续使用深色 Reading Glass、白色媒体文字和深色小型玻璃按钮。

## 顶部窗口层级

窗口结构保持 `WindowChrome → ActionBar → FilterBar → Queue`，不改变业务位置。

本轮只修复真实截图暴露的问题：

- 输入元素显式使用 `appearance: none`，取消浏览器原生文本框绘制，避免自定义 `TextField` 内出现第二层边框和填充。
- 操作栏继续使用 `48px` 高度，控件使用 `32px`，图标按钮使用 `28px–32px`。
- `添加` 保持紧凑弱强调；网页识别、搜索、批量操作和设置保持次级。
- 不改变标题栏与业务操作分层，也不把输入框放回窗口标题层。

## 组件边界

### React

`MediaTaskBanner.tsx` 只保留：

- 任务行为与命令。
- 图片加载、失败和天然尺寸状态。
- `classifyArtwork` 与 `classifyArtworkTone` 的结果。
- `data-media-quality`、自动生成的 `data-artwork-tone`、密度、任务状态和进度宽度。

删除根容器、图片、玻璃、文字、元信息和操作区的旧内联视觉常量。动态进度宽度可以继续使用内联 CSS 自定义属性或宽度值。

删除现有供调用方手工指定的 `artworkTone` 属性和三套内联明暗覆盖，但保留由真实图片自动生成的 `data-artwork-tone` 作为 CSS 语义输入。真实应用与开发画廊统一由图片尺寸、加载结果和亮度采样决定构图与染色；测试通过模拟图片天然尺寸和采样结果覆盖分类分支，不保留只为画廊服务的生产组件开关。

### CSS 与令牌

- `media-task-banner.css` 成为横幅视觉的唯一来源。
- `tokens.css` 提供媒体环境层、焦点层、Reading Glass 和降级所需语义令牌。
- 同步修订 `docs/UI-DESIGN-LANGUAGE.md` 的亮度自适应降级：真实图片无法采样时由 `medium` 改为保守的 `light`，以真实任务对比度优先。
- 不再依赖大量 `!important` 与旧内联样式竞争；仅允许针对第三方或不可控遗留样式的最小覆盖。
- 开发画廊继续复用生产组件，不再拥有能掩盖生产缺陷的专属材质规则。

## 状态、交互与可访问性

- 保留 `pending / downloading / paused / completed / failed / cancelled` 状态与现有主要操作。
- 状态继续使用文字和小圆点，不只依赖颜色。
- 横幅本身不是大按钮；打开、暂停、继续、重试和更多操作保持独立焦点。
- 右侧按钮在所有媒体质量和主题下保持可读边界与焦点环。
- 标题仍为单行省略，元信息保持可扫读；超长标题不得把操作推出横幅。
- `prefers-reduced-transparency` 和应用减少透明设置必须保留完整信息与操作。

## 测试与验收

### 自动化

- 为 `classifyArtwork` 覆盖标准横图、低分辨率横图、竖图、无效尺寸和窗口缩放后的重新分类。
- 为 `classifyArtworkTone` 覆盖三档阈值，并覆盖 Canvas 可采样与 CORS/读取失败时回退为 `light`。
- `MediaTaskBanner` 测试覆盖 `standard / weak / missing` 的 DOM 层级、自动亮度数据属性、错误回退和现有任务动作。
- 主题令牌测试证明浅色主题没有覆盖媒体文字与 Reading Glass 深色语义。
- 配置测试证明新配置默认 `dark`，已有 `light / dark / system` 值读取与保存语义不变。
- 顶部输入框测试证明只有一个可见控件外壳，并保留键盘焦点环。
- 现有 UI 聚焦测试、TypeScript 构建和生产 Vite 构建全部通过。

### 真实 Electron

使用现有 3 个真实任务进行最终验收：

1. 深色主题、推荐窗口尺寸：整体层级接近视觉基准。
2. 浅色主题：窗口为浅色，但三张媒体横幅文字和按钮均清晰可读。
3. 当前低清四合院缩略图：不得再以巨型像素和黄色文字铺满整张横幅。
4. 当前亮色网页缩略图：标题不得再出现白字压白底。
5. 顶部链接输入框：不得再出现双层输入框。
6. `760px` 最小宽度：标题省略，主要操作可用，无水平溢出。
7. 减少透明：材质降级但信息层级保持完整。

最终截图必须来自真实 Electron；开发画廊截图不能作为通过依据。
