# v0.2.2 首次使用安装包冒烟设计

- 日期：2026-08-26
- 所属版本：v0.2.2（安装与首次使用可靠）
- 分支：`chore/v0.2.2-first-use-smoke`
- 依赖：`fix/v0.2.2-safe-diagnostics`
- 状态：采用

## 1. 用户结果

每次生成 Windows 或 macOS 安装包时，自动化不再只证明 Electron 进程短暂存活，而要证明安装包内的桌面端已经连上 Sidecar、扩展桥可以接收链接、任务能够出现在桥查询结果中，并且打包后的 Sidecar 可以生成结构正确的安全诊断包。

这项冒烟用于尽早拦截“能构建但首次使用不可用”的候选；它不能替代真实机器上的安装、可见窗口、完整下载、退出和卸载验收。

## 2. 当前证据缺口

`scripts/test_packaged_electron.mjs` 当前只做以下事情：

1. 启动打包后的 Electron；
2. 等待 8 秒；
3. 只要进程没有提前退出就判定通过；
4. 强制终止进程。

因此以下故障仍可能得到假绿：Sidecar 永远未握手、桥端口由旧进程占用、`/health` 一直未就绪、`/enqueue` 失败、任务写入后桥仍返回 `unknown`。脚本也没有给 Sidecar 设置独立数据目录，可能读取或污染运行器已有状态。

`scripts/test_packaged_sidecar.mjs` 已验证 hello、ping、Telegram offset 和 shutdown，但没有调用 `app.exportDiagnostics`，也没有检查冻结态生成的 ZIP 是否符合安全诊断成员合同。

## 3. 方案比较

### 方案 A：继续仅检查进程存活

改动最少，但无法证明任何首次使用结果，不采用。

### 方案 B：增强现有黑盒脚本（采用）

不修改生产协议，不增加测试专用 HTTP 端点：

- Electron 脚本从外部轮询现有 `127.0.0.1:17888/health`；
- 就绪后通过现有 `/enqueue` 提交一条不会携带 Cookie 的公开 smoke URL；
- 再通过现有 `/tasks` 确认任务 ID 可查询且不是 `unknown`；
- Sidecar 脚本通过现有 `app.exportDiagnostics` 导出 ZIP；
- 用纯 Node ZIP 中央目录读取器检查固定四个成员，无需额外运行时依赖。

优点是覆盖真实生产接口，脚本同时适用于 Windows 与 macOS；缺点是仍无法观察用户窗口和安装器交互。

### 方案 C：在生产应用增加 smoke 专用端点或环境分支

可以自动退出并导出更完整收据，但会让测试控制面进入生产主进程，当前收益不足，不采用。

## 4. Electron 冒烟合同

### 4.1 隔离与防串线

- 启动前请求桥健康端点；若已有任何 HTTP 响应，立即失败，避免误验旧 Downany 进程。
- 所有请求使用短超时；连接拒绝才表示端口空闲，其他异常也要保守失败。
- 每次运行使用独立临时根目录：Electron `--user-data-dir` 与 `DOWNANY_DATA_DIR` 分开建立子目录。
- 设置 `DOWNANY_UPDATE_DISABLED=1`，避免冒烟触发外部版本检查。

### 4.2 就绪

- 启动后最多等待 90 秒，覆盖未签名包首次校验与慢盘。
- `/health` 必须返回 HTTP 2xx、`ok: true`、`service: downany-bridge`、`sidecarReady: true`。
- 等待期间若 Electron 提前退出，立即失败，并附带限长 stderr。

### 4.3 入队与可见性

- POST `/enqueue` 一条固定公开 URL，必须返回 HTTP 2xx、`ok: true`、`count: 1` 和唯一非空 `taskIds[0]`。
- GET `/tasks?ids=<id>` 必须返回同一 ID，状态不得为 `unknown`。
- 不要求该 URL 下载成功；脚本确认的是首次使用入口与队列可见性，完整下载由真实 URL 回归承担。

### 4.4 收敛

- 成功或失败都必须终止本次 Electron 进程树并清理自建临时目录。
- 用户显式传入的目录不由脚本删除。

## 5. Sidecar 冒烟合同

- 在 ping 与 shutdown 之间调用 `app.exportDiagnostics`。
- 返回值必须为 `ok: true`，绝对 ZIP 路径必须位于传入的 `DOWNANY_DATA_DIR/diagnostics` 内。
- ZIP 必须存在、为普通文件、大小大于零，成员精确为：
  - `environment.json`
  - `failed_tasks.json`
  - `logs/summary.json`
  - `privacy.json`
- 成员读取器只解析 ZIP 中央目录，拒绝截断、重复成员、越界长度、加密条目和非法 UTF-8 名称。
- 最后仍要通过协议 `app.shutdown` 并观察零退出码。

## 6. 测试与 CI

- 新增纯 Node 单元测试，覆盖桥未占用、桥就绪重试、提前退出、入队响应、任务查询，以及有效/截断/重复 ZIP 中央目录。
- 单元测试在普通 `desktop` CI 的 Node 20 环境运行，不等待发布打包任务才发现脚本错误。
- 现有 tag / workflow_dispatch 的 Windows 与 macOS 安装包步骤继续调用同名脚本，因此无需新增另一套发布路径。

## 7. 完成边界

本子项目完成只证明：冒烟工具能够对打包 Sidecar 和打包 Electron 的首次使用核心接口给出更强证据，并已在当前 Windows 环境完成可用候选抽检。完整 v0.2.2 仍需要：

- 安装入口与安全诊断分支获得集成授权；
- Windows 安装器在干净目录或测试用户下完成可见安装、启动、退出和卸载；
- 真实 macOS 完成 DMG 安装与启动验收；
- 至少一条真实公开媒体完成下载并打开结果；
- 版本准备、三件同源产物与公开发布授权。
