# v0.2.2 Install Entry Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Chrome extension's unavailable install destination with the live GitHub Release page and make every install fallback show user-ready guidance.

**Architecture:** Add one extension-local global module that owns the release fallback URL and can run in Chrome MV3, a normal extension page, and Node tests. The service worker and install page consume that module; a Node contract test locks the URL, script ordering, product copy, and CI wiring without introducing a browser framework.

**Tech Stack:** Chrome Manifest V3, plain JavaScript, HTML/CSS, Node.js 20 `assert`, GitHub Actions

**Spec:** `docs/superpowers/specs/2026-08-26-downany-v0-3-staged-upgrade-design.md`

## Global Constraints

- Keep Electron + Python Sidecar as the only product line; this increment changes only the Chrome extension, its documentation, and CI test wiring.
- Use `https://github.com/JackEngineer/downany/releases/latest` as the live fallback destination.
- User-visible copy may describe only the product object, user action, current state, and result; it must not mention placeholders, deployment status, repository development commands, the HTTP bridge, or implementation flow.
- If the desktop app is merely stopped, preserve the existing `downany://open` wake attempt and bridge retry before showing install guidance.
- Do not deploy a website, bind a domain, bump a version, merge, push, create a tag, or publish a Release.
- Do not add a runtime dependency or a build step to the extension.
- Use TDD and create a local commit after each independently testable task.

## File Map

- Create `browser-extension/install-target.js`: the only runtime owner of the live Release fallback URL; exports through both `globalThis.DownanyInstallTarget` and CommonJS for Node tests.
- Create `browser-extension/install-target.test.js`: Node contract test for the shared URL, service-worker consumption, install-page fallback, user copy, and CI invocation.
- Modify `browser-extension/background.js`: load and consume the shared install target; remove internal install guidance from notifications and comments.
- Modify `browser-extension/install.html`: provide a working no-script link and user-ready installation guidance; load the shared target before `install.js`.
- Modify `browser-extension/install.js`: consume the shared target and show user-facing readiness states.
- Modify `browser-extension/README.md`: document the real GitHub Release fallback rather than a placeholder site.
- Modify `.github/workflows/ci.yml`: execute the new contract test in the extension job.

- [ ] **Step 3: Add the environment-neutral target module**

Create `browser-extension/install-target.js`:

```javascript
"use strict";

(function attachInstallTarget(root) {
  const api = Object.freeze({
    DOWNLOAD_URL: "https://github.com/JackEngineer/downany/releases/latest",
  });

  root.DownanyInstallTarget = api;
  if (typeof module === "object" && module.exports) {
    module.exports = api;
  }
})(typeof globalThis === "object" ? globalThis : this);
```
