# v0.2.2 首次使用安装包冒烟实施计划

> 目标：用现有生产协议把“进程活着”升级为“Sidecar、诊断导出、扩展桥、入队和任务可见性真实可用”的跨平台安装包冒烟。

**设计文档：** `docs/superpowers/specs/2026-08-26-v0.2.2-first-use-smoke-design.md`

## Task 1：先锁定黑盒 helper 合同

- [ ] 新建 `scripts/package_smoke_helpers.test.mjs`，先导入尚不存在的 helper 模块并观察失败。
- [ ] 测试桥端口未占用、未就绪重试、就绪成功和子进程提前退出。
- [ ] 测试入队成功合同与 `/tasks` 同 ID、非 `unknown` 合同。
- [ ] 用内存 ZIP fixture 测试固定成员、截断、重复成员和越界中央目录。

命令：

```powershell
node --test scripts/package_smoke_helpers.test.mjs
```

## Task 2：实现无依赖 helper

- [ ] 新建 `scripts/package_smoke_helpers.mjs`。
- [ ] 所有 HTTP 请求支持注入 `fetch`、明确超时和限长错误正文。
- [ ] 等待循环同时观察子进程退出状态，不使用固定睡眠判定成功。
- [ ] ZIP 解析只返回经过 UTF-8 校验和边界检查的中央目录成员。
- [ ] 运行 Task 1 测试直至通过。

## Task 3：增强打包 Electron 冒烟

- [ ] 重构 `scripts/test_packaged_electron.mjs` 使用 helper，并保留现有命令行参数兼容。
- [ ] 启动前确认桥未被其他进程占用。
- [ ] 隔离 Electron user-data 与 Downany data 目录，并关闭更新检查。
- [ ] 等待真实 `/health` 就绪，再经 `/enqueue` 和 `/tasks` 验证固定 smoke 任务。
- [ ] 所有退出路径收敛进程树和自建临时目录。

## Task 4：增强打包 Sidecar 冒烟

- [ ] 在 `scripts/test_packaged_sidecar.mjs` 中调用 `app.exportDiagnostics`。
- [ ] 校验返回路径在指定数据目录内、ZIP 为非空普通文件。
- [ ] 用同一 ZIP helper 校验四个固定成员。
- [ ] 保留 Telegram offset 与优雅 shutdown 现有检查。

## Task 5：接入普通 CI 与验证

- [ ] 在 `.github/workflows/ci.yml` 的桌面 job 中运行 helper 单元测试。
- [ ] 运行 Node 20 helper 测试。
- [ ] 运行完整 Python 测试、桌面测试与生产构建。
- [ ] 构建或定位当前源码对应的 Windows 打包 Sidecar，运行增强后的 Sidecar smoke。
- [ ] 若存在可证明来源的 Windows unpacked Electron 候选，运行增强后的 Electron smoke；否则明确记录缺失，不以旧候选替代当前源码证明。
- [ ] 检查 diff、工作区和提交范围后提交本地分支；不合并、不推送。

## 完成边界

该计划不执行安装器安装/卸载，不创建 tag，不发布 Release，也不把本地 Windows 结果当作 macOS 通过。真实双平台可见验收继续保留为 v0.2.2 发布门槛。
