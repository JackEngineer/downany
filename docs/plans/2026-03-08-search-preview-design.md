# 搜索列表预览能力设计（封面图 + 直接查看视频）

## 1. 背景与目标

当前搜索标签页已支持结果列表、详情信息与“打开链接/下载选中”，但缺少可视化预览能力。用户期望新增：

- 搜索列表展示封面缩略图；
- 选中结果后可在应用内直接预览视频；
- 若应用内预览失败，自动回退到浏览器打开。

本设计聚焦“可用性优先”，在不破坏下载主流程的前提下为搜索页增加预览体验。

## 2. 约束与范围

### 2.1 约束

- 保持现有双栏布局（左侧结果列表，右侧详情区）；
- 不改变下载队列数据结构与状态机；
- 封面采用懒加载策略，仅加载可视区；
- 预览策略采用“应用内优先，失败回退浏览器”。

### 2.2 本次范围（In Scope）

- 列表项封面缩略图；
- 详情区大封面与预览入口；
- 预览失败自动回退浏览器；
- 预览与封面相关状态提示。

### 2.3 非目标（Out of Scope）

- 新增平台搜索源；
- 下载格式选择与高级播放控制；
- 完整媒体库功能（收藏、播放历史）；
- 重构下载核心模块。

## 3. 方案对比与决策

### 方案 A（采用）：详情区内嵌预览

- 在现有搜索页内完成“列表封面 + 右侧预览”闭环。
- 改动面集中，学习成本低，交互路径最短。

### 方案 B：独立预览弹窗

- 播放区更大但会增加窗口管理复杂度。
- 与当前“单页双栏”风格一致性较弱。

### 方案 C：列表内展开播放

- 交互最短，但滚动与渲染复杂度高，性能风险大。

**结论：采用方案 A。**

## 4. 设计方案

### 4.1 组件划分

1. **封面加载层**
   - 负责封面异步下载、缓存命中、失败占位图回退；
   - 基于可视区触发，避免一次性拉取全部封面。

2. **预览控制层**
   - 负责“准备可播地址 -> 启动应用内预览 -> 失败回退浏览器”的状态机；
   - 与下载逻辑解耦，避免污染任务状态。

3. **详情展示层**
   - 展示标题、元信息、链接、大封面、预览状态与操作按钮；
   - 维持现有“下载选中/复制链接/打开链接”能力。

### 4.2 关键数据流

1. 搜索完成后渲染列表项（先占位图，后异步替换封面）；
2. 用户滚动列表时，仅对可视项触发封面加载；
3. 用户选中项后，详情区更新文案与大封面；
4. 点击“直接预览”后：
   - 优先尝试应用内预览；
   - 失败则自动回退浏览器；
   - 回退失败时提示并保留“复制链接”兜底。

### 4.3 状态与错误处理

- 封面失败：展示失败占位图并写入短时失败缓存；
- 预览失败：明确提示并自动浏览器回退；
- 快速切换选中项：仅允许“当前选中项”更新详情区，忽略过期异步回调；
- 资源释放：切换页面/关闭窗口时释放预览资源。

## 5. 验收标准

### 5.1 功能

- 搜索列表可显示封面缩略图（懒加载生效）；
- 右侧详情区展示大封面并支持“直接预览”；
- 预览失败时自动回退浏览器并有可理解提示；
- 现有下载与链接能力无回归。

### 5.2 性能与稳定性

- 搜索结果首屏渲染不被封面加载阻塞；
- 快速滚动不卡死；
- 连续切换结果不串项；
- 异常网络场景下不崩溃，可优雅降级。

## 6. 测试计划（手工）

- YouTube / Bilibili 各验证至少 5 条结果；
- 代理开启/关闭各执行一轮；
- 封面成功、超时、403 各执行一轮；
- 预览成功与失败回退路径均覆盖。

## 7. 风险与缓解

- **平台限制导致不可播**：以浏览器回退保证可达；
- **封面防盗链导致失败**：失败缓存 + 占位图降低抖动；
- **异步回调串项**：绑定当前选中上下文并校验后更新 UI。

## 8. 里程碑建议

1. 封面懒加载能力接入；
2. 详情区预览入口与状态提示接入；
3. 预览失败回退策略接入；
4. 回归测试与体验打磨。
